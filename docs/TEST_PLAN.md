# テスト方針

「検証可能な最小構成から進める」ため、物理を描画から切り離し、**ヘッドレスで決定論的に検証できる部分を自動テストの中心**にします。

## 1. 自動テスト（`npm test`, Vitest / Node）

ルール：
- 物理側（`src/sim/`）は Three.js・DOM を import しない。テストは描画なしで回す。
- 期待値は「物理的にあり得る範囲」で書く（例：転がり加速度 ≈ 5/7·g·sinθ）。マジックナンバーの完全一致テストは決定論テストに限定する。
- 物理パラメータを変えたら physicsProfile を更新し、決定論テストは自己比較なのでそのまま通る。将来のゴールデン値（後述）は更新理由を記録して差し替える。

## 2. 実ブラウザのスモークテスト（`tests/e2e/smoke.cjs`）
Playwright で開発サーバーを開き、以下を確認（実行例）：
```bash
npm run dev &
PLAYWRIGHT_MODULE=/path/to/playwright node tests/e2e/smoke.cjs ./shots
```
- デスクトップ：再生→tick増加、一時停止→tick停止、1ステップ→+1、リセット→tick 0・初期位置、右ドラッグで視点回転、ホイールでズーム、Space で再生
- iPad Pro 11 エミュレーション（タッチ）：1本指ドラッグで回転（注視点は不変）、ピンチで距離変化、2本指ドラッグで注視点移動、ボタンの tap で再生、ボタン寸法 ≥ 44pt
- ページエラー・console.error が 0 件
- スクリーンショットを保存（目視確認用）

2026-10-11 時点、ヘッドレス Chromium（SwiftShader）で全項目通過。ソフトウェア描画のため FPS は低く、「処理落ち」表示が出ることも確認（仕様通りの挙動）。

### 配置編集（`tests/e2e/edit.cjs`）
iPad Pro 11 エミュレーションの実タッチ操作で確認：レールをタップして削除→パレットから追加→何もない所のドラッグは視点回転（部品は動かない）→レールのドラッグで rail_2 の出口に吸着・接続し、視点は動かない→再生すると発射機から球が出る→実行中にレールに触れると初期状態に戻って選択→回転・元に戻す→重なる位置へのドロップは理由付きで拒否→何もない所のタップで選択解除。ページエラー 0 件。背景（D-28）を入れてからソフトウェア描画が重くなったため、画面の大きさとタッチは iPad のまま画素密度だけ 1 にし、操作のあとは描画が2コマ進むのを待つ。

### ステージ（`tests/e2e/stage.cjs`）
起動時のステージ選択（1-1 以外はロック）→1-1 を選ぶ→パレットはレール（残り1）だけ→固定のレールは動かせない（理由表示）→レールを追加すると残り0→正しい位置に置いて再生→クリア画面→進捗が保存される→「次のステージへ」で 1-2→ステージ選択に「✓ クリア済み」、1-2 が開き 1-3 以降はロックのまま。smoke/edit は最初に「自由研究」を押してから始める。ページエラー 0 件。

## 4. 今後追加するテスト（手順2以降）
- **端末横断の決定論**：tick 100/500/1000/… の状態ハッシュ（量子化後）をゴールデン値として保存し、Chrome/Safari/Firefox・iPad で比較。不一致時の扱い（`INCOMPATIBLE`）を検証。
- **ポート接続**：型不一致（ball/shaft/signal）の拒否と理由表示。
- **隠しバグ（最初の3種）**：発動条件の境界値、同一seed での発動tick一致、safetyBudget 上限。
- **永久機関**：静止・見かけのループ・出力なし・オブジェクト上限超過を **誤認定しない** ことを先に負例テストで固める。
- **設計図JSON**：不正JSON・巨大入力・重複ID・未知ID・範囲外数値・`__proto__` 等のキー・スクリプト文字列を拒否／実行しない。
- 性能：球数・装置数を段階的に増やした時の物理 ms/tick の計測（ベンチマークを別スクリプト化）。
