# BUGWORKS ステージ・チュートリアル設計 v1.0

Claude Code実装前の企画・仕様案です。既存のマスター仕様書に追加して使用してください。

## 設計原則
- 初回5分で「置く→動かす→試す→発見する」を体験する。
- 通常クリアは隠しバグを必要としない。隠しバグは寄り道・発見・高度な解法に使う。
- 失敗にペナルティを設けず、即リトライ・巻き戻し・一手戻すを提供。
- 3D自由カメラ。iPad向けタップ／ドラッグ／ピンチ操作を優先し、マウス操作も用意。
- オフライン動作。設計図はローカル保存とJSON入出力のみ。
- 永久機関認定はゲーム内ルールによる検証であり、現実の永久機関の証明ではない。

## 初回5分の体験（目標時間。実測で調整）
| 時間 | 画面・体験 | ユーザー操作 | S-404の台詞 | 成功条件 |
|---|---|---|---|---|
| 0:00-0:30 | 研究所の作業台とゴールを見せる | カメラを回す | 「ここが実験室です。たぶん安全です。」 | カメラ回転を一度実行 |
| 0:30-1:20 | 既設レールの欠損を埋める | レールをドラッグ配置・スナップ | 「空いているところ、気になりますね。」 | レールが接続済み |
| 1:20-2:00 | 鉄球を転がす | 再生を押す | 「物理法則は、だいたい守られます。」 | 球がゴール到達 |
| 2:00-2:40 | 傾斜を変えて再実験 | レール角度を調整 | 「違う置き方も試せます。」 | 2回目の実行 |
| 2:40-3:30 | バネ装置を設置 | バネを接続し球を跳ね上げる | 「反発力って便利ですね。」 | 球が上段に到達 |
| 3:30-4:20 | 不思議な挙動の任意のヒント | 青い異常光を観察・再試行 | 「……いまのは仕様です。」 | 異常の存在を認識（発見は任意） |
| 4:20-5:00 | ステージ選択と設計図保存 | 名前を付けて保存 | 「再現できるなら、研究成果です。」 | ローカル保存成功 |

### 隠しバグの初回導入
- 初回5分ではバグを強制発動させない。S-404のセリフと環境演出だけで疑問を残す。
- ステージ1-3で「同じ条件で3回試す」など、観察によって到達可能な最初の発見機会を用意。
- 初発見時に短い演出と図鑑登録。発動条件の完全な答えは図鑑に表示しない。

## 共通操作・UI
- 再生、一時停止、リセット、1ステップ実行、元に戻す、やり直し、保存。
- カメラ: 1本指ドラッグで回転、2本指ドラッグで平行移動、ピンチでズーム（iPad想定）。選択中の部品操作と衝突しないモード分離を行う。
- 配置時はスナップ候補をハイライトし、接続不可なら赤く表示。回転ハンドルと接続方向矢印を表示。
- 最初のステージではヒントは段階表示。一定時間の経過だけで勝手に正解配置しない。
- アクセシビリティ: 色以外にアイコン/文字で状態を表現、演出点滅を減らす設定、字幕ON/OFF。

## 判定と保存
- ステージの通常クリア条件とバグ発見条件を別イベントで判定する。
- 設計図にはステージID、装置ID、接続ポート、座標、姿勢、装置設定、ゲーム仕様バージョンを記録。
- インポート時にバージョンと装置制約を検証し、破損/未対応ファイルは安全に拒否する。
- 連結設計図は別IDとして保存し、永久機関検証を再実行する。

## 未決定・検証が必要な項目
1. 既存40バグ定義との具体的なステージ配置対応（既存JSONを読み込んで確定）。
2. 物理エンジン選定と120Hz固定ステップ時のiPad性能計測。
3. 操作衝突（カメラ移動と装置ドラッグ）のユーザーテスト。
4. 各ステージの目標時間、失敗率、ヒント表示頻度。
5. チュートリアル用の研究所レイアウトと初期装置配置データ。

## Claude Codeへ渡す実装順
1. 1-1のレイアウトとタッチ/マウス操作を実装。
2. 物理再生・停止・リセットと通常クリア判定を実装。
3. 保存/再読込の再現性を検証。
4. 1-2〜1-5を実装し、バグ発見イベントを独立させる。
5. 実機テスト後、章2以降を段階追加。
