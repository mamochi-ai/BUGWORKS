# BUGWORKS 永久機関成立判定仕様 v0.1

## 目的と定義
BUGWORKSの「永久機関」は**ゲーム内の物理ルールおよび意図的な隠しバグを用いた、外部入力なしで反復運転が可能な装置**を指す。現実の永久機関を意味しない。サーバーでの長時間連続稼働は不要。

### 成立条件
1. **閉じた系**：検証開始後、プレイヤーの操作、外部からのエネルギー・物体の追加、無限に補充される通常の燃料はない。装置内部の隠しバグによるエネルギー付与・物体複製は許可し、由来を記録する。
2. **再帰状態**：位置・速度・角速度・接続状態・装置内部状態・タイマー位相・バグ状態を含む状態が、ある時点と後の時点で許容誤差内で一致する。単なる球の位置一致では不可。
3. **持続性**：候補周期を複数回再生して同じ状態へ戻り、稼働が停止しない。基準は初期案として3周期（変更可能）。
4. **有用な動作**：少なくとも1つの指定出力ポートで、各周期に正の仕事・信号パルス・物体搬送などの実際の出力イベントが発生する。空回りや静止状態は不可。
5. **再現性**：設計図、エンジンバージョン、物理定数、乱数シードを固定して再検証可能。未対応の外部スクリプトは実行しない。

## 判定ステータス
- `NOT_TESTED`：未検証
- `RUNNING`：検証中
- `CANDIDATE`：周期候補を検出
- `VERIFIED`：複数周期と出力条件を確認
- `INCONCLUSIVE`：時間・計算量上限などで未確定（失敗ではない）
- `FAILED`：停止、破損、入力要求、状態乖離などで不成立
- `INCOMPATIBLE`：互換性のない設計図・物理エンジン

## 検証フロー
1. 設計図を読み込み、スキーマと装置・接続数・パラメータの上限を検査。
2. ワールドを初期化し、固定時間刻み（例：1/120秒）で決定論的にシミュレーション。演出用パーティクルやUIは判定状態から除外。
3. ウォームアップ後、定期的に状態の正規化・量子化を行い、状態ハッシュで候補周期を探索。ハッシュ一致だけで合格させない。
4. 候補の2状態を数値比較し、位置・速度・角速度・装置内部状態・バグ位相・物体数などを照合。識別子に依存しない物体の対応付けを行う。
5. 候補周期を3回再生し、出力イベントを各周期で検証。隠しバグの発動条件も毎回一致させる。
6. 合格時に検証証明書（ローカルJSON）を発行。検証バージョンと設計図ハッシュを紐付ける。

## 重要な例外・安全策
- 浮動小数点演算は環境差がある。厳密な完全一致ではなく、量子化+誤差許容+再シミュレーションで判定する。Webブラウザや端末間での再現性は別途検証が必要。
- 無限増殖は**物理オブジェクト数上限**を設定。上限到達時は検証を`INCONCLUSIVE`または`FAILED`とし、黙って複製を省略して合格させない。
- 見かけ上の周期が非常に長い機関、準周期・カオス系は検出できない場合がある。その場合は`INCONCLUSIVE`。
- 瞬間的なエネルギー保存則の破れはゲーム内バグとして認めるが、通常の外部電源やプレイヤーの操作を隠しバグ扱いしない。
- **判定の偽陽性を防ぐことを優先**。完璧な数学的「永遠の証明」ではなく、定義された条件下でのゲーム内認定であると表示する。
- ゲーム内タイムリミットは端末性能に応じて設ける。検証が重い場合はワーカー等へ分離するが、ブラウザが固まらないよう段階的に実装。

## 設計図と連結
- 設計図JSONは `schemaVersion`, `engineVersion`, `physicsProfile`, `seed`, `devices`, `connections`, `ports`, `initialState` を保持。
- 他人の設計図の取り込み時は、装置IDを名前空間付きで再割当てし、座標系・スケール・ポート種別・向きを検証。
- **連結後は別の機関**と見なし、元の認定を引き継がず再検証する。
- 設計図ファイルには任意のJavaScript等を含めない。JSONデータのみを許可し、サイズ・配列長・数値範囲を検査。
- サーバー不要。ユーザーがJSONファイルをダウンロードし、他人に直接渡して共有する。

## 検証証明書
`certificate.example.json` を参照。証明書はプレイヤーの自慢・共有用の**ローカル検証結果**であり、第三者による改ざん耐性や公開ランキングを保証するものではない。信頼性が必要な場合は受け取った側が設計図を再検証する。

## UI
- 検証中：進捗、周期候補、出力イベント数、使用バグ、停止/キャンセル
- 成立時：「永久機関 認定！」、機関名、周期（ゲーム内秒）、出力、使用バグ、再検証ボタン、設計図書き出し
- 未確定時：「判定できませんでした」＋理由（計算上限、長周期、互換性など）
- 認定は「永遠に実稼働した」という主張ではないことをヘルプに明記。

## 推奨実装順
1. レール+鉄球だけで簡易状態スナップショットと周期検出
2. 歯車・バネ・磁石の内部状態を追加
3. 出力ポート・外部入力判定
4. 隠しバグの位相・再現性の照合
5. JSON保存/読込と再検証
6. 他人の機関との連結、性能最適化
